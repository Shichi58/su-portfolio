Fidelity Investments

UX Design Intern on Portfolio M.R.I., a portfolio analysis and optimization tool for internal portfolio managers. The work covered the optimization workflow, the simulation and risk visualizations, and a concept redesign of the brokerage dashboard.

The problem

01

Portfolio M.R.I. let managers upload a portfolio, set optimization constraints, and see the resulting risk and return distribution. Everything was on one screen at once: instrument table, four metric cards, a simulation histogram, an optimization panel, and a scenario panel.

The screen was dense because the task is dense - a portfolio manager genuinely needs all of it. But nothing was prioritized. Optimization controls sat at the same visual weight as the results they produced, so it wasn't obvious which panel you were meant to act in and which one you were meant to read.

Key decisions

02
Decision 01

Progressive disclosure on the optimization panel

The tension: Max Allocation and Loss Tolerance are the two controls that change everything downstream, but they were buried in a collapsed accordion at the bottom of the page, below the fold.

I made the optimization panel expand in place with the controls laid out horizontally - method and drawdown on the left, the two sliders taking the full width beside them. Optimize and Update sit at the end of the control flow rather than floating separately, so the sequence reads left to right: choose method, set constraints, run.

Decision 02

Two views of the same risk data

The tension: Default probability across 30-odd positions is a proportion question and a ranking question at once. One chart can't do both well.

I built the same data as a treemap and a donut. The treemap answers which positions carry the most risk, because area encodes magnitude directly. The donut answers how risk is distributed, because the eye reads a circle as a whole. Both use one green scale, and hovering either surfaces the same tooltip - asset ID and probability.

Decision 03

Original versus proposed as an overlay, not a toggle

The tension: The point of optimizing is the difference between where you are and where you'd be. A toggle makes the user hold one state in memory to compare it to the other.

Original and proposed render in the same histogram, green and amber, with a shared legend. The comparison is spatial rather than remembered. The hover tooltip returns the exact range, frequency, and default probability rather than only the bucket.
